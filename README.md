## 更新日志与提交

首次克隆后执行 `npm run hooks:install` 启用本仓库的提交检查。每次修改后，助手按 [AGENTS.md](AGENTS.md) 检查实际 Git Diff，自动整理中文 [CHANGELOG.md](CHANGELOG.md)，同日追加去重并保留历史。分类为新增功能、交互优化、视觉调整、问题修复，仅保留非空分类；每条说明涉及的页面或模块及具体变化。

提交前将实现与日志一起暂存，执行 `npm run changelog:check` 检查；`npm run changelog:message` 根据新增日志生成简洁中文候选说明。不提供提交说明时，Git Hook 自动填入候选说明；显式提供的中文说明会保留。Hooks 只检查格式、历史保留和同次提交，产品语义由助手依据 Diff 核实。相关检查可运行 `npm run test:changelog`。只有明确要求更新 GitHub 时才 push。

## 完整任务流程
- 机场接送使用五阶段顺序状态：开始出发 → 到达上车点 → 接到乘客 → 送达目的地 → 服务结束。按天包车使用相同接驾步骤，按目的地逐段送达，每个中间站送达后点击“开始出发”进入下一段，最后一站送达后结束服务。
- 每阶段包含 AI 主动提醒、下一步按钮和输入建议；点击空输入框填入建议，发送后推进。旧阶段按钮不可重复执行，关闭对话后保留进度。
- 联系客户：整理话术 → 发送 → 确认沟通结果 → 归档。明日任务完成行前确认，不提前开始出车。
- 订单支持调价后确认接单；自建任务支持整理要求、记录处理结果与完成归档。
- 所有路线、游客回复、消息发送和服务推进均为本地交互模拟，不连接外部服务；刷新清空状态。

新建任务改为对话输入，本地按首句提炼标题、保留补充内容作为说明，并更新同一任务卡片。接送阶段自动展示接近及到达通知，不再提供重复联系按钮；接送结束提示不展示金额。此原型仍使用本地规则模拟 AI 总结和游客通知，不调用真实消息服务。

新建任务现为直接问答入口：对话和提炼的标题、说明仅进入历史任务，可重新打开继续问答，不创建首页待办。常见司导问题的回答与摘要使用本地规则模拟，尚未连接通用大模型。

## 连续语音对讲
打开即通过 getUserMedia 请求麦克风，SpeechRecognition 开启 continuous 与 interimResults；“字”开关显示临时转写与完整对话。用户说话、AI 回答、静音和错误使用不同提示，按钮和光球提供轻微反馈。播报时暂停识别以避免识别自身声音，播报完毕恢复；关闭对讲或卸载页面释放媒体轨道、取消识别和播报。权限拒绝及不支持识别的浏览器显示重试/兼容性提示，不伪装成功。
语音捕获与转写依赖浏览器语音服务，不保存音频文件。回答与任务指令仍为本地规则模拟：支持上下文查询、出发（需先完成出车准备）、接单/接到游客（需匹配阶段）、通知草稿，以及“发布”模拟发送，不连接真实订单和消息平台。新建任务页共用语音开关、对讲入口及微信样式胶囊按钮。
